# Локальный разбор конкретных записей питания

Это отдельный локальный checkpoint, не окончание модернизации и не новая версия production.

## Что добавлено

- В обзоре питания показываются до трёх отдельных записанных порций с наибольшей энергией за выбранный период: название, день, масса, вклад в учтённые калории и КБЖУ. Отдельно выделяется записанная порция с наибольшим количеством белка. Выбор и вычисления используют полную точность; округление применяется только в интерфейсе.
- Можно ввести собственный вариант массы порции и увидеть расчёт разницы КБЖУ. Это сравнение будущего варианта, оно ничего не записывает и не удаляет из дневника.
- Показывается число записей без дополнительных показателей и число записей с оценочным составом. Даже частично заполненный состав может быть неполным; по нему нельзя делать вывод о дефиците.
- На главной есть краткая локальная подсказка на основе записей выбранного дня и переход в подробный обзор. При отсутствии записей нет выдуманной сводки. Дневник и его данные для этого никуда не отправляются.
- Явно указано, что старый Gemini-обзор по-прежнему получает агрегаты, а не отдельные порции. Его `JournalOverview.request` не расширен новыми локальными данными.

Это детерминированный подсчёт, а не ответ ИИ. Самый калорийный продукт не объявляется вредным, а сравнение порций — необходимым действием. Возраст, неподтверждённые цели и профиль в расчёт не подставляются. Личную рекомендацию, разбор причин и полноценное сравнение замен пользователь запросил отдельно: это задача нового AI-раздела с отдельным предварительным просмотром и согласием.

## Проверки и ограничения

`test/nutrition_insights_test.dart` — шесть тестов точности, отсутствия/нуля, сравнения без записи, приватности старого запроса, экрана шириной 320 px и перехода с главной. `checks/nutrition_overview_regression_retry.log`: overview 6/6, старый preview 1/1, nutrition insights 6/6, навигация 15/15. Из-за расширившейся ленивой прокрутки в тесте предпросмотра добавлена прокрутка к прежней кнопке; функциональный тест по-прежнему проверяет отмену и подтверждённую передачу. `checks/nutrition_analyze.log` — статический анализ без ошибок.

`checks/nutrition_build_o1.log` — проверочная web-сборка без Supabase-ключей (оптимизация O1, wasm dry-run отключён из-за лимита памяти; это не production-сборка). `checks/nutrition_upgrade.json` — изолированное обновление 3.0 → локальная версия и офлайн, 14/14 синтетических проверок; Supabase заблокирован. Предыдущая версия через реальную синхронизацию и Android в этом checkpoint не проверялась. Пропуск нутриента остаётся неизвестным. Локальная сводка не определяет качество рациона, не оценивает нормы и не обещает обнаружить все проблемы.
