# Условная оценка прогресса упражнений — локальный кандидат

Это отдельный **незавершённый этап**, а не разрешение выпуска. На production-клиенте функции пока нет. Расчёт не меняет документы тренировок, цели или настройки и не отправляет историю ИИ.

## Как устроено

В истории упражнения кнопка открывает предупреждение; расчёт выполняется только после подтверждения. Данные заново читаются из локального хранилища. Для каждого подходящего занятия выбирается подход с наибольшей оценкой по формуле Эпли: `вес × (1 + повторения / 30)`. Сравниваются два последних **подходящих** занятия, округление — только при показе. Если записи отсутствуют, они не превращаются в нули. Если время начала двух нужных занятий совпадает, порядок не угадывается и изменение не рассчитывается.

Учитываются подходы на 2–10 повторений с положительным весом, без времени и технического теста. Записи с режимами подтягиваний и названиями, содержащими `подтягив`, исключаются. Важно: произвольное пользовательское название подтягивания может не распознаться, если режим также не указан; не следует использовать эту оценку для упражнений с собственным весом. Предупреждение в интерфейсе нуждается в уточнении этой границы до выпуска.

Результат приблизителен, не является измеренным максимумом и не рекомендует вес для тренировки. Он особенно условен при разной технике, оборудовании, амплитуде и усилии. Запас повторений не используется формулой, лёгкие подходы могут давать заниженную оценку. Приложение не предлагает работать до отказа или пробовать максимум. Одинаковое название не доказывает сопоставимость упражнений.

Прежняя попытка при одновременной веб-сборке завершилась ошибкой компилятора; это сохранённая историческая ошибка, причина не доказана.
