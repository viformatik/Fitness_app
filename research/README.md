# Частичные исследования — только синтетика, не релиз

Здесь сохранены уцелевшие материалы, а не полная воспроизводимая лаборатория. Не подключать реальные аккаунты, облака или браузерные профили, не открывать реальную базу, не развёртывать приложение. Файлы здесь не являются готовым исправлением.

## Что удалось сохранить

- [`atomic_writer_lab/`](atomic_writer_lab/) — новая изолированная лаборатория: Chromium и Firefox подтвердили, что точная архивная +14 может перезаписать результат отдельной синтетической атомарной транзакции. Прототип writer — не новый клиент приложения. Там же сохранены модельные проверки Web Locks и вариантов версий, результаты и ограничения.
- `available_results/race_{chromium,firefox}_initial.json`: в каждом отчёте 14 проверочных условий PASS, 2 воспроизведённых риска и 0 FAIL. В одноразовой сети без внешних маршрутов две старые вкладки, использующие точную +14, после начальных 250 мл каждая записали 500 мл. Результат — 500, хотя три отдельных действия предполагают 750. Значение не изменилось и после офлайн-перезапуска. Это одно расписание, а не доказательство поведения каждого сценария.
- `historical_reports/verification_before_file_loss.json`: сводка 41 проверки **до последующей утраты файлов**. Она не подтверждает нынешнюю комплектность. В том прежнем исследовании два браузера также показали риск несовместимости старой +14 с версией IndexedDB v2 (`VersionError`); соответствующие подробные отчёты и исходные harness-файлы в этой ветке отсутствуют. Старые отчёты `coordination_*`, `fast_recovery_*`, `food_secure_*` — исторические, их исходная среда не сохранена полностью.
- `fixtures/archived_v14_fitness_worker.js` — worker архивной +14, SHA-256 `c82632c6495999fcca11ee3eaad2b56a44c48432fa1ec65384aefd2896750a49`. Полная веб-сборка здесь намеренно отсутствует: она содержит встроенный публичный ключ подключения, а эта ветка не публикует ключи. Отдельный архив +14, доступный в пользовательской копии 004, имел SHA-256 `457e5da0b9d7da6d55e29c712428b52a84d8b626a4c7af39a3501cdcb4d5ae02`. Сам по себе worker не является приложением.
- `partial_harness/` — уцелевшие вспомогательные файлы для прежней лаборатории. Исходники `offline_fence_probe.cjs` и `offline_stale_race_probe.cjs`, на которые они ссылаются, отсутствуют; структура директорий изменилась. Не заявляем, что эти скрипты запускаются или воспроизводят отчёты из этой ветки. В отчётах сохранены SHA-256 отсутствовавших источников для проверки, если они найдутся.
- `surviving_prototypes/` и `surviving_tests/` — старые отдельные исходники, сохранённые для изучения. Они не встроены в раннее приложение, могут требовать отсутствующие зависимости и фикстуры и не проходили здесь нового полного регресса.
- `sql_v1_unverified/` — ранний SQL и старый синтетический отчёт. **Не применять SQL.** SHA-256 сохранённого `food_search_upstream_budget_v1_as_sent_test.sql`: `148e919d7b8cc247856529db963cc76c42da5dee4a3e122eba6f150a6c127b81`. В прежнем `off_budget_postgres_v3.json` записан другой SHA SQL (`e0b7a0ce1f23471a3aba2f822ff85fd2c596280372c5c880603bde225f07b448`), поэтому тот результат не подтверждает побайтовое тестирование сохранённого SQL.
- `base_reconstruction_history/` — историческая инструкция и скрипт, сохранённые для происхождения данных. Bundle и patch не включены: они могут содержать Git-историю и непроверенные материалы. Без них этот исторический скрипт не восстановит исходное полное дерево.

Публичная ветка — лишь безопасно отобранная часть. Для продолжения с точным состоянием 004 сначала необходим пользовательский архив с совпадающей контрольной суммой; затем нужно отдельно проверить всё, что предполагается публиковать. Архив 003 был утрачен и его не следует подменять этим ранним снимком.

Команда `python3 research/verify_preserved.py` автономно проверяет структуру двух сохранённых отчётов, зафиксированные ими числа и SHA worker. Она не запускает браузер и не воспроизводит эксперимент.

Тесты двух браузеров не подтверждают поведение Safari/iOS, Android, разных устройств, питания, Auth, облачной синхронизации или реального восстановления пользовательской копии. Принудительный offline сетевого namespace — не физический режим полёта и не проверка потери питания.
