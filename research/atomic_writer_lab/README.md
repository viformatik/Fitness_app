# Лаборатория смешанных записей — только синтетика

Это исследование, не код приложения и **не исправление**. В каждом запуске создаются свежий Playwright context, случайный loopback-origin и новые вымышленные базы; процесс работает не от root в отдельном Linux network namespace без внешних маршрутов. Профили браузера, дневник, аккаунты, облако и production не используются. Браузерные процессы и временный профиль удаляются при завершении. Сценарии за пределами изолированной сети отказываются запускаться до открытия браузера.

## Новые результаты

В Chromium 141.0.7390.37 и Firefox 142.0.1 получены одинаковые результаты. Полные числовые отчёты и SHA исходников — в `results/`.

| Эксперимент | Результат | Предел вывода |
|---|---|---|
| Две **модельные** вкладки: обе читают и увеличивают число внутри одной readwrite-транзакции | В 10 раундах каждого браузера получено 750 из 250 + 250 + 250 | Не проверяет код приложения и не доказывает корректность всех расписаний |
| Модельная «старая» вкладка заранее прочитала 250, новая записала атомарно 500, старая затем записала свои 500 | Итог 500 вместо ожидаемых 750 | Это демонстрация одного порядка действий |
| Web Locks: участник с тем же lock ожидал, но другой код записал в IndexedDB, вообще не запрашивая lock | Запись прошла во время удержания lock | Web Locks координирует только участников протокола; это не проверка всех механизмов приложения |
| Модельное повышение IndexedDB с v1 до v2 | Открытое соединение v1 блокирует upgrade; после закрытия upgrade проходит, а запрос с явно заданной v1 получает `VersionError` | Не испытываются устройства, аварии и реальный откат |
| Две отдельные модельные базы | Разные имена позволили открыть v1 и v2, но пара значений `500/500` получена и от двух независимых добавлений, и от одного добавления с последующим копированием | Одни текущие значения не содержат историю действий; дополнительное достоверное происхождение может изменить вывод |
| **Точная архивная +14** и отдельный синтетический атомарный writer | В обоих браузерах +14 сохранила устаревшие 500 после атомарной записи второго writer; ожидаемые три действия дали бы 750. Сохранение старой вкладки завершилось, новое открытие UI и БД показало 500 | Второй writer — не настоящий новый клиент и не полная реализация Hive. Имена БД перенаправлены в одноразовую фикстуру; добавлены наблюдение вызовов записи и accessibility. Проверен один порядок, локальный сервер оставался доступным; это не тест офлайн-перезапуска |

Для последнего опыта проверены 27 файлов архивной фикстуры; три фактически загруженных `main.dart.js` совпали с закреплённым SHA, у второй и открытой заново страницы ответ пришёл от worker. Внешние запросы страницы блокировались маршрутизатором Playwright (24 в Chromium, 28 в Firefox), а network namespace не имел внешних маршрутов. Данные были выдуманными. У каждого браузера: **7 диагностических условий PASS, 1 RISK_REPRODUCED, 0 FAIL**. Это не означает, что риск устранён.

В первом диагностическом Chromium-запуске `attempts/chromium_archived_mixed_initial.json` получил **FAIL**, потому что тест ошибочно ожидал отображения нуля: пустая +14 пишет «Вода не записана». Исправленная проверка различает отсутствие записи и ноль; исходник первой попытки сохранён по его SHA. Этот отказ был ошибкой предположения теста, а не доказательством ошибки приложения.

## Повторение, если действительно нужна отдельная лаборатория

Только в disposable Linux-окружении без реальных данных. Нужны `sudo -n`, `unshare`, `ip`, `setpriv`, Node, системные зависимости для браузеров и Playwright 1.56.1. Установка пакетов и браузеров скачивает файлы из интернета; сами пробы работают только в отдельном loopback namespace. Для запуска нужны именно свежие имена отчётов: существующие файлы не перезаписываются.

```sh
cd research/atomic_writer_lab
npm ci --ignore-scripts --no-audit --no-fund
export NODE_PATH="$PWD/node_modules"
export PLAYWRIGHT_BROWSERS_PATH="$(mktemp -d)"
./node_modules/.bin/playwright install chromium firefox
REPORTS="$(mktemp -d)"
./run_isolated.sh chromium "$REPORTS/chromium-model.json"
./run_isolated.sh firefox "$REPORTS/firefox-model.json"
python3 verify_results.py  # сверяет сохранённые в репозитории отчёты, не новые
```

Для опыта с **точной +14** дополнительно нужен отдельно полученный архив `archived_v14_web.tar.gz` с SHA-256 `457e5da0b9d7da6d55e29c712428b52a84d8b626a4c7af39a3501cdcb4d5ae02`. Его нет в этой ветке: внутри скомпилированного клиента находится встроенный публичный ключ, а ключи в публичную ветку не добавлялись. Он был частью сохранённого пользователем 004. Распаковывайте только вне Git, например из корня этой ветки:

```sh
python3 research/partial_harness/prepare_fixture.py \
  --archive /path/to/archived_v14_web.tar.gz --output /tmp/fitness-v14-fixture
cd research/atomic_writer_lab
./run_archived_isolated.sh chromium /tmp/fitness-v14-fixture "$REPORTS/chromium-v14.json"
./run_archived_isolated.sh firefox /tmp/fitness-v14-fixture "$REPORTS/firefox-v14.json"
```

Распаковщик сначала проверяет SHA архива и безопасные пути, а probe повторно проверяет SHA **каждого из 27 файлов**. Неверная фикстура и запуск вне network namespace проверены на отказ до открытия браузера. Не копируйте распакованную сборку в публичный репозиторий.

Никакая комбинация этих тестов не проверяет реальный дневник, Safari/iOS, Android, Auth, облако, многопользовательскую синхронизацию, сбой питания или восстановление настоящей копии. Не применять миграции и не развёртывать ничего на основании этих результатов.
